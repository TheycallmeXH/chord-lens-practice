# v1.0.0 正式版验证

## 自动化范围

- 25 项纯逻辑测试，遍历 6,252 组字典和弦、根音、转位与八度重复组合。
- 5 级、15 类、32 种和弦的 12 调、音区和转位；18 套进行的移调与就近转位。
- 超时提示的暂停排除、重试保留、下一题重置；共同音衔接与持续按住不重复计分。
- 标准 MIDI 文件音轨、速度变化、非鼓组过滤、起音窗与拍长分组、实际组成音、未知音集和大小限制。
- 导入预览、切换音轨、空选择、坏文件保留旧练习、重练原序列；关于版本、固定仓库入口及授权文件白名单。
- MIDI Note On / Off、力度零、重复触发、延音、选择延音、多设备与通道、控制器清音。
- 练习保持时间、松键切题、逐音补齐、错音与重试、跳过、暂停计时、指定音区、记录保存与导出。
- 1120×740、1280×800、1480×960、1920×1080 布局、长和弦名、密集音集、音程标签与五度圈。
- 面板折叠、侧栏边缘开关、布局恢复、键盘操作与状态持久化。
- 320×200 极简窗口、280×180 最小窗口、完整窗口恢复、最大化与置顶。
- 原生 Windows 窗口顺序检查：完整与极简窗口反复开启 / 取消置顶，模拟层级切换时被其他窗口抢到前面，确认窗口恢复前台且高于其他普通窗口。
- 每次启动声音与 MIDI 试听默认开启；单一音频上下文复用，采样产生输出，总静音消除输出并暂停处理。
- 损坏记录不阻止启动；设备同步打开失败与过期异步失败不会破坏替换设备。
- 原生 Electron MIDI 权限请求成功，`sysex:false`。
- 真实端口检查必须运行 `npm run test:midi:native`，确认已连接设备可枚举并打开；不能用模拟输入测试替代该检查。
- MIDI 服务请求和端口打开均有 5 秒超时；超时后可以刷新重试，过期请求不会覆盖新连接，健康连接刷新不会重新请求系统授权。
- 五套配色 × 三种模式 × 四种窗口尺寸，在浏览器和原生桌面分别检查模式功能显隐、琴键高度、密集音集下的布局与音程边界。
- 配色持久化、无效配置回退、练习中换肤不重置音符与进度、标题栏颜色与明暗模式、极简窗口同步。
- 五套配色的当前和弦说明、情绪、低音、五度圈小调、键盘音区、当前导航与极简窗口信息文字对比度均至少 4.5:1。
- 暂停时隐藏跳过按钮，继续后恢复；结束练习后立即恢复五度圈调性应用按钮。
- SF2 默认 Akai `piano1`；检查非零采样音频输出与钢琴路径没有创建振荡器，覆盖力度、重复落键、延音、A4 调音、目标试听、总静音和重启默认开启。
- 已加载音色复用；发声和静音状态均可更换 SF2，保留 MIDI 状态；静音后音频上下文暂停。
- SF2 音频测试隔离实体 MIDI 请求，使用模拟消息；本机 Equinox 与分发版 Akai 分别测试。测试期间曾遇到系统 MIDI 请求持续等待，实体设备与驱动的连接状态需单独检查。

## 性能回归

自动化测试在空闲状态观察到 0 次 DOM 变更；连续 10,000 条不改变音符的 CC64 消息没有触发重复和弦分析或 DOM 重绘。控制器处理耗时只反映当前测试机器，不是对其他硬件的性能保证。

只有练习正在运行或节拍器启用时才启动 25 ms 定时更新。和弦分析有聚合上限，避免持续 MIDI 输入无限延迟显示。

## 已知边界

真实 MIDI 权限与已连接端口可在本机检查；自动化演奏使用模拟消息。不同品牌键盘、驱动、USB 热插拔时序与长时间实际练琴仍需在各自设备上验证。未签名的 Windows 应用可能触发发布者提示。音集存在命名歧义，听感标签不是情绪预测。

2026-11-15 本机 Windows MIDI 服务发生卡死：应用请求与独立 WinMM 设备枚举均无响应。清理应用残留进程不能恢复；重启卡死的 `midisrv` 后，同一原生测试能够识别并打开 Arturia KeyLab Essential 61 的两个真实输入端口。此项验证确认端口连接，实际琴键事件仍需用户弹奏确认。
